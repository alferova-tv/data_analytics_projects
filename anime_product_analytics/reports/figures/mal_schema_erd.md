# MyAnimeList — схема данных

Диаграмма построена по трём таблицам датасета Kaggle «Anime Dataset (Jan 1917 – Oct 2025)».
`details` хранит характеристики самих тайтлов — жанры, оценки, популярность, даты выхода.
`ratings` — взаимодействия отдельных пользователей с разными тайтлами.
`stats` — агрегированные по каждому тайтлу показатели.

Часть полей на диаграмме скрыта — они не используются в проекте.
Интерактивная версия: [`mal_schema_erd.html`](mal_schema_erd.html).

| Таблица | Колонок | Ключи |
|---|---|---|
| `details` | 29 | 1 PK |
| `ratings` | 6 | 1 FK, 1 UNIQUE |
| `stats` | 27 | 1 PK + FK |

## ERD

```mermaid
erDiagram
    details ||--o{ ratings : "mal_id → anime_id (one : many)"
    details ||--|| stats : "mal_id → mal_id (one : one)"

    details {
        integer mal_id PK "Id аниме на MyAnimeList, уникальный идентификатор тайтла"
        text title "Название аниме на английском"
        varchar type "Формат: ТВ-сериал, фильм, OVA и т. д."
        varchar status "Статус показа: транслируется, завершён, ожидается"
        real score "Оценка аниме пользователями по 10-балльной шкале"
        real scored_by "Число пользователей, оценивших аниме"
        varchar start_date "Дата начала показа"
        varchar end_date "Дата окончания показа"
        real rank "Позиция в общем рейтинге аниме по оценке"
        integer popularity "Рейтинг популярности на основе интереса пользователей"
        integer members "Общее число пользователей, добавивших аниме в свои списки"
        integer favorites "Число пользователей, отметивших аниме как любимое"
        text genres "Список жанров аниме"
        text studios "Студии анимации, участвовавшие в производстве"
        text themes "Тематические теги сюжета"
        varchar demographics "Целевая аудитория, например Shounen или Seinen"
        varchar source "Первоисточник: манга, ранобэ, оригинальный сценарий"
        varchar rating "Возрастной рейтинг, например PG-13 или R"
        real episodes "Общее число эпизодов"
        varchar season "Сезон выхода: зима, весна, лето, осень"
        real year "Год выхода"
    }

    ratings {
        varchar username "Уникальный ник пользователя"
        integer anime_id FK "Id аниме, с которым связана запись"
        varchar status "Статус просмотра: смотрю, завершено, отложено, брошено, планирую"
        integer score "Оценка аниме пользователем по 10-балльной шкале"
        real is_rewatching "Признак повторного просмотра"
        integer num_watched_episodes "Число просмотренных пользователем эпизодов"
    }

    stats {
        integer mal_id PK "Id аниме, он же FK на details.mal_id"
        integer watching "Число пользователей, смотрящих аниме в данный момент"
        integer completed "Число пользователей, завершивших просмотр"
        integer on_hold "Число пользователей, временно приостановивших просмотр"
        integer dropped "Число пользователей, бросивших просмотр до завершения"
        integer plan_to_watch "Число пользователей, планирующих посмотреть аниме"
        integer total "Общее число пользователей, добавивших аниме в свои списки"
        real score_N_votes "N = 1..10, десять колонок: число голосов с оценкой N"
        real score_N_percentage "N = 1..10, десять колонок: доля голосов с оценкой N"
    }
```

**Связи**

- `ratings` → `details` — многие к одному по `anime_id = mal_id`. Один пользователь может взаимодействовать со многими тайтлами, один тайтл — с многими пользователями; в таблице уникальна пара `(username, anime_id)`.
- `stats` → `details` — один к одному по `mal_id`. Проверено в [`01_data_quality.ipynb`](../../notebooks/01_data_quality.ipynb): обе таблицы по 28955 строк, наборы ключей совпадают в обе стороны.

Блок оценок в `stats` записан как 20 отдельных колонок — `score_1_votes` … `score_10_votes` и `score_1_percentage` … `score_10_percentage`. На диаграмме они свёрнуты в две строки с `N` вместо номера, чтобы не растягивать схему.

## Data dictionary

### `ratings`

| Поле | Тип | Описание |
|---|---|---|
| `username` | varchar(50) | Уникальный ник пользователя |
| `anime_id` | integer | Id аниме, с которым связана запись |
| `status` | varchar(50) | Статус просмотра: смотрю, завершено, отложено, брошено, планирую посмотреть |
| `score` | integer | Оценка аниме пользователем по 10-балльной шкале |
| `is_rewatching` | real | Признак того, что пользователь пересматривает аниме повторно |
| `num_watched_episodes` | integer | Число просмотренных пользователем эпизодов |
